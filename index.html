Warm-up: answer in five seconds

A bat and a ball cost $1.10 in total. The bat costs $1.00 more than the ball. How much does the ball cost?

Cognitive Reflection Test item (Frederick, 2005), discussed in Kahneman (2011), ch. 3.

\[ b + (b + 1.00) = 1.10 \;\Rightarrow\; 2b = 0.10 \;\Rightarrow\; b = 0.05 \]

More than half of students at several elite universities gave 10 cents, the answer that feels right. Kahneman's point: System 1 offers an answer instantly, and System 2 is too lazy to check it.

For language models: one forward pass per token is the model's System 1. The fluent continuation wins unless the prompt makes it check.

[2:00–5:00] Read the question aloud. Give them five seconds, then ask for a show of hands: who got 10 cents? Type a couple of answers into the box. Then show the algebra.

Key line: the wrong answer is not random; it is the most available one. A language model decoding greedily behaves the same way: it emits the highest-probability next token, and "10" is a very probable token after "costs $0.". Everything in Part 2 is about buying the model a moment to check.

Two systems, two kinds of prompting

System 1 fast, automatic

Human: reading a face, 2 + 2, completing "bread and …".

Model: one forward pass per output token. Fixed work per token: about \(2P\) FLOPs for \(P\) parameters, and a fixed serial depth \(L\) (the number of layers).

System 2 slow, effortful

Human: 17 × 24, filling a tax form, checking an argument.

Model: generating intermediate tokens. Each written token is fed back in, so \(T\) reasoning tokens give \(T \cdot L\) serial steps and a scratchpad to remember them.

\[ \text{System 1: } \;\text{compute} \approx 2P \cdot |y| \]
\[ \text{System 2: } \;\text{compute} \approx 2P \,\big(|r| + |y|\big) \]

Thinking tokens \(r\) are the only knob that changes how much computation a frozen model spends on a question.

The thesis of today's class: fast prompts change which distribution the model samples from; slow prompts change how much computation it does before answering.

Kahneman (2011), ch. 1–2. Serial-depth argument: Merrill & Sabharwal (ICLR 2024); Feng et al. (NeurIPS 2023).

[5:00–8:00] Kahneman's System 1 is automatic and effortless; System 2 allocates attention to effortful work. The analogy to transformers is surprisingly precise. For every token, the model runs the same fixed stack of layers: same FLOPs, same depth. It cannot "think harder" about a hard token. The only way to give it more computation is to make it write more tokens, because each written token becomes input for the next step.

Theory backs this: Merrill and Sabharwal show transformers with a chain of thought can solve problems that fixed-depth transformers provably cannot, and the power grows with the number of intermediate steps. Remember the thesis line on the right; we'll test every technique against it.

The one equation behind every technique

A frozen model defines a conditional distribution. A prompt \(x\) is the condition.

\[ p_\theta(y \mid x) = \prod_{t=1}^{|y|} p_\theta\big(y_t \mid x,\, y_{\lt t}\big) \]

Prompt engineering searches over inputs, never over weights:

\[ x^{\ast} = \arg\max_{x}\; \mathbb{E}_{(q,a)\sim\mathcal{D}}\Big[\, m\big(\operatorname{decode}\, p_\theta(\cdot \mid x \oplus q),\; a\big) \Big] \]

\(\oplus\) concatenation, \(m\) a metric such as exact match, \(\mathcal{D}\) the task distribution.

Decoding: the model's first impression

\[ p_i(T) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)} \]

\(T \to 0\): greedy, always the top token. \(T = 1\): the model's own distribution. \(T \to \infty\): uniform.

Top-p: keep the smallest set of tokens whose probability sums to at least \(p\), renormalise, sample.

Prompt: "…How much does the ball cost? The ball costs $" — next-token logits are illustrative.

Sample the next token

[10:00–12:00] Set temperature to 0.05: the model always says 10 cents. That is System 1 with no noise. Raise temperature to 1 and sample a few times: sometimes 5 cents appears. This matters later: self-consistency needs diverse samples, so it uses temperature around 0.5–0.8, not 0. Ask: why would top-p 0.6 never produce 5 cents here? Because the top token alone already holds most of the mass at low temperature.

Part 1 · Fast prompts System 1

Zero-shot: specify, don't hint

PromptRole: You review loan applications.
Task: Classify the email as COMPLAINT,
  QUERY or OTHER.
Context: Customers write in Hinglish too.
Constraints: If unsure, choose OTHER.
Format: Reply with one word only.

Email: "loan ka status kya hai? 3 din ho gaye"

Instruction-tuned models map instructions directly to behaviour. Each component removes a degree of freedom the model would otherwise guess.

\[ H\big(Y \mid x_{\text{full}}\big) \;\le\; H\big(Y \mid x_{\text{short}}\big) \]

On average, conditioning on more relevant information cannot increase uncertainty. Specificity narrows the output distribution.

Kahneman link: System 1 fills gaps with whatever comes to mind first. An under-specified prompt invites the model to do the same.

[12:00–14:00] Walk the five labels. The maths point: conditional entropy. Adding relevant conditions to the prompt can only narrow the distribution of outputs on average. Vague prompts leave many plausible continuations; the model picks the most typical one, which is rarely the one you meant. Note the caveat "on average": a single misleading detail can still hurt a particular case.

Few-shot: show, don't tell

Review: "Stopped charging after a week." →

GPT-3 showed that a large model can learn a task from a few examples in its context, with no gradient update (Brown et al., 2020).

What do the examples actually teach?

Min et al. (2022) replaced the labels in demonstrations with random labels. Accuracy dropped only a little on many classification tasks.

So demonstrations mostly specify the label space, the input distribution and the format, more than the input–label mapping itself.

Practice: 3–8 diverse examples, balanced across labels, in random order, in exactly the output format you want.

Brown et al. (NeurIPS 2020); Min et al. (EMNLP 2022).

[14:00–16:00] Few-shot is the most powerful fast technique. The surprising Min et al. result tells us what the examples are doing: they tell the model which task, which labels, which format. The next slide gives the cleanest mathematical explanation of why that works.

Few-shot as Bayesian inference: the number game

\[ p(y \mid x, S) = \sum_{h} p(y \mid x, h)\, p(h \mid S) \]
\[ p(h \mid S) \propto p(h) \prod_{i=1}^{k} \frac{\mathbb{1}[s_i \in h]}{|h|} \]

The model infers a hidden task \(h\) from demonstrations \(S\) (Xie et al., ICLR 2022). The \(1/|h|\) term is the size principle: specific concepts that fit win fast (Tenenbaum, 1999).

Click numbers to add examples. Shading = predicted probability that a number belongs to the concept.

[16:00–19:00] Start with just 16: the posterior is spread over "even", "powers of 2", "squares", ranges. Add 8, 2, 64: powers of 2 jumps to near certainty, because under "even numbers" each example has likelihood 1/50 while under "powers of 2" it has 1/7. With four examples the ratio is (50/7)^4, about 2,600 to 1. That is the size principle. Now try 16, 23, 19, 20: a range wins. Ask the class to predict before clicking.

The lesson for prompting: demonstrations are evidence about which task you want. Few, well-chosen, diverse examples identify the task faster than many similar ones.

Anchors inside prompts, and how to remove them

Majority-label bias: the model favours labels frequent in the demonstrations. Recency bias: it favours the label of the last example. Common-token bias: it favours frequent words (Zhao et al., 2021).

Jones & Steinhardt (2022) adapted anchoring and framing tests from psychology and found matching failures in code-generating models.

Contextual calibration

Feed a content-free input such as "N/A" to measure the prompt's built-in bias \(\hat p_{\text{cf}}\), then divide it out:

\[ W = \operatorname{diag}(\hat p_{\text{cf}})^{-1},\qquad \hat q = \operatorname{softmax}\big(W\,\hat p(y\mid x)\big) \]
Worked examplep(y | "N/A")      = [0.70 pos, 0.30 neg]
p(y | real input) = [0.60 pos, 0.40 neg]

W·p = [0.60/0.70, 0.40/0.30]
    = [0.857, 1.333]
→ normalised = [0.39 pos, 0.61 neg]

Raw output says positive; once the prompt's own lean is removed, the evidence says negative.

Practice: balance labels, shuffle order, and calibrate when you read label probabilities.

Zhao et al. (ICML 2021); Jones & Steinhardt (NeurIPS 2022).

[22:00–24:00] The prompt itself is an anchor. If four of five demonstrations say positive, the model leans positive. Calibration is simple Bayes: measure what the model says when there is nothing to read, treat it as the prior, divide it out. Work the numbers on the right: 0.60 over 0.70 and 0.40 over 0.30, normalise, the decision flips. The full derivation is in the handout.

Framing: same facts, different answers

Tversky & Kahneman (1981): 600 people face a disease. With outcomes framed as lives saved, 72% chose the sure option. With the same outcomes framed as deaths, 78% chose the gamble.

Models have a sharper version: format sensitivity. Changing separators, casing or spacing in a few-shot prompt moved LLaMA-2-13B accuracy by up to 76 points on one task (Sclar et al., ICLR 2024).

Practice: never report one prompt. Evaluate several equivalent framings and report the spread.

Prompt ensembling removes framing noise

\[ \bar p(y \mid q) = \frac{1}{K}\sum_{k=1}^{K} p_\theta(y \mid x_k \oplus q) \]

If each framing has error \(\varepsilon_k\) with variance \(\sigma^2\) and pairwise correlation \(\rho\):

\[ \operatorname{Var}\Big(\tfrac{1}{K}\sum_k \varepsilon_k\Big) = \sigma^2\Big(\rho + \frac{1-\rho}{K}\Big) \]

Averaging removes the independent part of framing noise, never the shared part \(\rho\sigma^2\). Keep this formula: it returns for self-consistency.

[24:00–26:00] The framing study: identical expected outcomes, opposite majority choices. For models, even meaningless formatting acts as a frame. The variance formula is the most reused formula in today's class; derive it on the board if time allows (handout section 4). With K framings, independent noise shrinks by 1/K, but correlated noise rho stays.

Roles and priming: what the evidence really says

Priming in humans

Kahneman devoted a chapter to priming studies. Many failed to replicate, and he later wrote publicly that he had placed too much faith in small, underpowered studies.

Personas in models

A systematic test of 162 roles in system prompts found that adding a persona did not reliably improve accuracy on factual questions compared with no persona (Zheng et al., Findings of EMNLP 2024).

does not follow, quote it, and say why.

Rule: a role helps when it imports audience, standards, format and constraints. It does not add intelligence.

[26:00–27:00] Keep this brief and honest. Kahneman himself is the best model of intellectual honesty here: when priming results failed to replicate, he said so. Same with personas: "you are an expert" is folklore. The useful part of a role is the specification it carries.

Part 2 · Slow prompts System 2

Chain-of-thought: write the reasoning down

\[ p(a \mid q) = \sum_{r} p_\theta(r \mid q)\; p_\theta(a \mid q, r) \]

The rationale \(r\) is a latent variable. Generating it first lets the answer condition on intermediate results the model could not compute in one pass.

Kahneman link: System 2 needs working memory. The context window is the model's working memory; CoT puts the intermediate results there.

[27:00–29:00] The equation: the answer probability marginalises over possible reasoning paths. Without CoT, the model must jump straight from q to a in one pass per token. Two famous numbers: Wei et al. with exemplars, Kojima et al. with five words. One caveat to state: in Wei et al. the gains appeared mainly in very large models; small models wrote fluent but wrong chains.

Why thinking tokens help: effort is serial

Kahneman opens with 17 × 24. You know you can do it, but it takes deliberate, step-by-step effort and your pupils dilate while you do.

Multiplying multi-digit numbers needs carries that depend on earlier carries: a serial computation. A transformer has fixed depth \(L\) per token, so it cannot do arbitrarily long serial work in a single token.

SettingSerial steps available
Answer immediately\(L\) per token
With \(T\) reasoning tokens\(\approx T \cdot L\)

Theory: constant-depth transformers without intermediate steps sit in a weak circuit class; with a polynomial number of CoT steps they can simulate any polynomial-time computation (Merrill & Sabharwal, ICLR 2024). Feng et al. (NeurIPS 2023) give the arithmetic case.

Corollary: "think step by step" helps tasks with serial structure (arithmetic, logic, multi-hop) and does little for pure recall ("capital of Peru").

[29:00–31:00] Ask everyone to compute 17 × 24 in their heads and type it; the widget times them. That felt like effort. Now the model: each token gets the same fixed depth. Long serial dependencies like carries cannot fit in one token's computation, but they fit across many tokens. That is the theoretical reason CoT helps arithmetic and doesn't help factual recall.

Self-consistency: many thoughts, one vote

  

    

      
Greedy CoT takes one path \(r\). The quantity we want sums over all paths. Sampling \(N\) paths and voting is a Monte Carlo estimate of it:

      
\[ \hat a = \arg\max_{a} \sum_{i=1}^{N} \mathbb{1}[a_i = a] \;\xrightarrow{N\to\infty}\; \arg\max_a \sum_r p(r,a\mid q) \]

      
Binary case, each sample correct with probability \(p\gt\tfrac12\), independent:

      
\[ P(\text{vote wrong}) \le \exp\!\big(-2N(p-\tfrac12)^2\big) \]

      
Hoeffding's inequality: error falls exponentially in \(N\) (Condorcet's jury theorem). If \(p\lt\tfrac12\), voting makes things worse.

    

    

      
56.5 → 74.4%
GSM8K, PaLM 540B: CoT vs self-consistency with 40 sampled paths (Wang et al., ICLR 2023).

      
Why it works better than the binary bound suggests: wrong answers usually scatter (₹10, ₹15, ₹4.5…) while right answers agree. A plurality can win with far less than 50%.

      
Cost: \(N\) times the tokens. Gains usually flatten after 10–20 samples.

    

  

  


[34:00–36:00] Self-consistency is the cleanest System 2 trick: sample at temperature around 0.7, extract each final answer, take the majority. Mathematically it approximates marginalising over reasoning paths. Hoeffding gives exponential decay of error when each path is better than chance. Important warning: when the model is usually wrong, voting amplifies the wrong answer. Derivation in handout section 6.

  







  
Kahneman's rule: keep the judges independent

  

    

      
Kahneman advises that before a meeting discusses an issue, each person should write a short summary of their own view. Otherwise the first speaker anchors everyone and the group's errors become correlated.

      
Same for samples. Model: with probability \(\rho\) all \(N\) samples copy one shared draw; otherwise they are independent.

      
\[ \text{Acc}_\rho(N) = \rho\,p + (1-\rho)\,\text{Acc}_0(N) \]

      
Decorrelating prompts: vary the exemplars, their order, the phrasing, or even the model, so the samples fail in different ways.

Decomposition: least-to-most, plan-and-solve, step-back

  

    

      
\[ p(a \mid q) \approx \prod_{j=1}^{m} p_\theta\big(s_j \mid q,\, s_{\lt j}\big)\cdot p_\theta(a \mid q, s_{1:m}) \]

      
Replace one hard step with a chain of easy ones. If each sub-step succeeds with \(p_j\), the chain succeeds with \(\prod_j p_j\): keep steps few and easy.

Self-critique works only with new evidence

  

    

      
WYSIATI: "What you see is all there is." System 1 builds the most coherent story from what is in front of it and ignores what is missing (Kahneman, 2011, ch. 7).

      
A model asked "are you sure?" sees the same context as before. Huang et al. (ICLR 2024) found that intrinsic self-correction, with no external feedback, often failed to improve reasoning accuracy and sometimes reduced it.

      
Critique helps when the loop adds information: unit tests, a calculator, a retrieved document, a compiler error (Reflexion: Shinn et al., NeurIPS 2023).

    

    

      
Voting vs verifying

      

        
SelectorSuccess with \(N\) samples

        
Majority voteneeds \(p\) to beat every wrong answer

        
Perfect verifier\(1 - (1-p)^N\)

      

      
With \(p = 0.3\) and \(N = 10\): voting often fails, a perfect checker succeeds with probability \(1 - 0.7^{10} \approx 97\%\). If you can check an answer, check it; don't vote.

    

  

  


[44:00–46:00] WYSIATI is Kahneman's best phrase for model behaviour: the model only knows what is in the context. Asking it to reflect without new information mostly re-runs the same System 1. Contrast the two selectors: with a reliable checker, coverage grows as 1 − (1 − p)^N, even when the model is usually wrong. That is why code agents run tests.

Base-rate neglect: the taxi cab problem

  

    

      
A cab was in a hit-and-run at night. 85% of the city's cabs are Green and 15% are Blue. A witness said "Blue", and in tests the witness is right 80% of the time. How likely is it the cab was Blue? (Tversky & Kahneman; Kahneman 2011, ch. 16)

      
\[ P(B\mid \text{“B”}) = \frac{0.8 \times 0.15}{0.8 \times 0.15 + 0.2 \times 0.85} = \frac{0.12}{0.29} \approx 0.41 \]

      
Most people say about 80%. Prompt fix: "First state the base rates, then update with the evidence," or ask for natural frequencies (Gigerenzer & Hoffrage, 1995).

\[ P(A \cap B) = P(A)\,P(B \mid A) \le P(A) \]

      
(b) can never be more probable than (a). In Tversky & Kahneman's (1983) studies a large majority still picked (b): the description is representative of a feminist, so the conjunction feels likelier.

      
Models: Binz & Schulz (PNAS 2023) found GPT-3 made human-like errors on several such vignettes, while noting the classic versions may be memorised. Hagendorff et al. (Nature Computational Science, 2023) saw intuitive errors on CRT-style items fall sharply in later chat models.

      
Prompt fix: ask the model to name the events, write the probability rule that relates them, then answer.

Availability: give the model the facts, don't trust recall

  

    

      
Availability heuristic: people judge how frequent something is by how easily examples come to mind (Kahneman 2011, ch. 12–13).

      
Models: accuracy on a fact tracks how often it appeared in pretraining data; rare, long-tail facts are answered much worse (Kandpal et al., ICML 2023).

      
Retrieval-augmented generation puts evidence in the context instead of relying on recall:

      
\[ p(y \mid q) \approx \sum_{d \in \text{top-}k(q)} p_\eta(d \mid q)\; p_\theta(y \mid q, d) \]

      
Lewis et al. (NeurIPS 2020).

Cite the document id for each claim.
If the answer is not in the documents,
say "not found".

[doc 3] … [doc 7] … [doc 12] …

Question: …

      
ReAct extends this into a loop: Thought → Action (search, calculator, code) → Observation → Thought… (Yao et al., ICLR 2023). Each observation is the new evidence that WYSIATI says the model lacks.

The prompt template on the right has three important lines: only these documents, cite ids, and permission to say "not found".

Quiz: pick the technique (click to reveal)

  

    
1. A sentiment classifier says "positive" 80% of the time, even on neutral text. Five of your six demonstrations are positive.
Anchoring by majority label. Balance and shuffle the demonstrations, then apply contextual calibration with a content-free input.

    
2. A model gets 40% on a hard maths set. Sampling 20 answers and voting barely helps. The wrong answers are usually the same wrong number.
Errors are correlated (and p < 0.5). Voting can't fix that. Use PAL for the arithmetic, or a verifier, and decorrelate samples by varying prompts.

    
3. You ask "are you sure?" after a wrong answer about a library function. The model changes a correct part instead.
WYSIATI: no new evidence. Give it something real: run the code, show the error message or the documentation, then ask it to revise.

    
4. A colleague adds a four-example chain-of-thought template to every prompt for a reasoning model. Accuracy drops.
Expected: the DeepSeek-R1 report found few-shot prompting degrades its performance. Use a zero-shot prompt with a clear specification and output format.
